## 📌 Постановка задачи

Разработать программу для управления доступом параллельных процессов к файлу по именованным каналам (named pipes). Программа включает процесс-сервер `Server` и несколько процессов-клиентов `Client`.

### Процесс `Server`:

1. Создать бинарный файл со структурой `employee`:
   ```cpp
   struct employee {
       int num;        // идентификационный номер
       char name[10];  // имя сотрудника
       double hours;   // количество отработанных часов
   };
   ```
   Имя файла и данные вводятся с консоли

2. Вывести созданный файл на консоль

3. Запустить заданное количество процессов `Client`

4. Обслуживать запросы клиентов через именованный канал:
   - **Модификация записи** — эксклюзивная блокировка записи для других клиентов
   - **Чтение записи** — множественный доступ для чтения, блокировка для записи

5. После завершения всех клиентов вывести модифицированный файл

6. Завершить работу по команде с консоли

### Процесс `Client`:

1. В цикле запрашивать операцию:
   - `r` — чтение записи
   - `m` — модификация записи
   - `e` — выход

2. Доступ к записям по ключу — `ID` сотрудника

3. **При модификации:**
   - Запросить ID записи
   - Получить запись с сервера и вывести на консоль
   - Ввести новые значения полей
   - Отправить изменённую запись на сервер

4. **При чтении:**
   - Запросить ID записи
   - Получить запись с сервера и вывести на консоль

## 🏗️ Архитектура

### Именованный канал
- **Имя канала:** `\\.\pipe\employee_pipe`
- **Тип:** `PIPE_TYPE_MESSAGE` (сообщения фиксированной длины)
- **Режим:** `PIPE_READMODE_MESSAGE`

### Глобальная синхронизация
- **Семафор:** `MutexAccess` — защита одновременного подключения к каналу

### Reader-Writer синхронизация на уровне записей

Для каждой записи создаётся структура `RecSem`:

| Поле | Назначение |
|------|------------|
| `readCountMutex` | Защита счётчика читателей |
| `resourceSem` | Эксклюзивный доступ к записи |
| `readCount` | Количество активных читателей |

**Алгоритм:**
- **Чтение:** увеличивает `readCount`, первый читатель блокирует `resourceSem`
- **Запись:** эксклюзивно блокирует `resourceSem`
- При завершении чтения: уменьшает `readCount`, последний читатель освобождает `resourceSem`

### Протокол обмена

| Направление | Данные | Описание |
|-------------|-------|----------|
| Client → Server | `char op` | Операция: 'r', 'm', 'e' |
| Client → Server | `int id` | ID сотрудника |
| Server → Client | `employee` | Данные записи (num=-1 если не найдена) |
| Client → Server | `employee` | Модифицированная запись (только для 'm') |
| Client → Server | `char 'f'` | Сигнал завершения операции |
