## Постановка задачи

Разработать программу, состоящую из потока `main` и нескольких экземпляров потока `marker`, с синхронизацией через критические секции и события.

### Поток `main`:
1. Захватить память под массив целых чисел (размер вводится с консоли)
2. Инициализировать элементы массива нулями
3. Запросить количество потоков `marker`
4. Запустить заданное количество потоков `marker`, передав каждому порядковый номер
5. Дать сигнал на начало работы всех потоков
6. В цикле:
   - Ждать, пока все `marker` не подадут сигнал о невозможности продолжения
   - Вывести массив на консоль
   - Запросить номер потока для завершения
   - Подать сигнал на завершение выбранному потоку
   - Дождаться его завершения
   - Вывести массив на консоль
   - Подать сигнал остальным потокам продолжить работу
7. Завершиться после завершения всех потоков

### Поток `marker`:
1. Ждать сигнал от `main` на начало работы
2. Инициализировать ГСЧ своим порядковым номером
3. В цикле:
   - Генерировать случайное число
   - Индекс = число % размер_массива
   - Если элемент == 0:
     - Задержка 5 мс
     - Записать свой номер в элемент
     - Задержка 5 мс
   - Иначе:
     - Вывести: свой номер, количество помеченных, недоступный индекс
     - Сигнал `main` о невозможности продолжения
     - Ждать сигнал от `main` (продолжить или завершить)
4. При завершении: заменить все свои элементы на 0

### 2. Механизмы синхронизации

| Механизм | C++ | Java |
|----------|-----|------|
| Критическая секция | `std::mutex` + `std::lock_guard` | `ReentrantLock` / `synchronized` |
| События / ожидание | `std::condition_variable` | `Phaser` / `CountDownLatch` |
| Атомарные флаги | `std::atomic<bool>` | `AtomicBoolean` |
| Ожидание потока | `thread.join()` | `Thread.join()` |

**Ключевые отличия:**

| Аспект | C++ | Java |
|--------|-----|------|
| Блокировка ресурса | `std::lock_guard<std::mutex>` | `lock.lock()` / `try-finally` |
| Освобождение блокировки | Автоматическое (RAII) | Ручное (finally) |
| Управление памятью | Ручное (`new`/`delete`) | Автоматическое (GC) |
| Обработка прерываний | Флаги + `condition_variable` | `interrupt()` + `AtomicBoolean` |
| Фазовая синхронизация | Самодельный `Barrier` | `Phaser` (встроенный) |

## Выводы

### Что оказалось проще в Java?
1. **Фазовая синхронизация** — встроенный `Phaser` избавил от ручной реализации барьера
2. **Управление памятью** — GC исключил необходимость в умных указателях
3. **Тестирование** — `ExecutorService` упростил многопоточные тесты
4. **Код короче** — отсутствие header-файлов и меньше шаблонного кода

### Что осталось сложным в обоих языках?
1. **Конкурентный доступ** — логика защиты разделяемого ресурса идентична
2. **Обработка прерываний** — в обоих случаях требуется аккуратное управление флагами
3. **Дедлоки** — риск остаётся одинаковым независимо от языка

### Что было проще в C++?
1. **RAII для блокировок** — автоматическое освобождение мьютексов
2. **Скорость выполнения** — нативные потоки быстрее JVM
3. **Контроль над задержками** — точные `sleep` на уровне ОС

### Итог

> За исключением синтаксического сахара и микро-нюансов с управлением памятью, код и его сложность оказались идентичными. Java-реализация получилась несколько лаконичнее за счёт встроенных средств синхронизации (`Phaser`), а C++ — более производительной и предсказуемой по времени.
